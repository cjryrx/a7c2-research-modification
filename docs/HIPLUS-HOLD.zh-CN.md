
# 按住按键切到 Hi+：设计方案与现状

目标：用户选一个按键；按下期间驱动模式切到 **连拍 Hi+**，松开恢复原状；其余时间相机行为不变。
固件在启动时读取存储卡上的配置文件：**文件不存在 = 功能不启用**；文件内容决定绑定哪个按键。

## 1. 配置文件

路径（待定，取决于这台机身的挂载点）：`/mnt/sdcard/A7C2_HIPLUS.CFG`

```
A7C2-HIPLUS
version=1
slot=0x041B          # 绑定到哪个按键槽
mode=hold            # hold = 按住生效；toggle = 按一下切换
hi_plus_value=3      # 驱动模式枚举里的 Hi+
```

PC 侧脚本：`tools/hip_plus_config.py --list` / `--slot 0x041B --out D:\A7C2_HIPLUS.CFG`。

## 2. 固件侧需要三件事，各自现状

| 环节 | 现状 | 难度 |
| --- | --- | --- |
| **A. 启动时读 SD 卡文件** | 未做。app 有文件访问能力（读写存储卡、播放音乐都用它），但需要在补丁代码里调用它的文件 API 或直接走 FAT 层 | 中 |
| **B. 把某个按键变成"加速键"** | 未做。自定义键的分发是**纯数据驱动**的（事件表无人引用、事件 id 无立即数），静态找不到入口 | 高 |
| **C. 切到 Hi+ 再恢复** | 部分可行。`PRM_HAITA_setting_menu_drive_mode` 等属性存在，但驱动模式切换走 `sequence_set_drive_mode::run()`，需要 0x68 字节、13 个字段齐全的模型对象 | 高 |

**结论**：这是一个完整的"自定义按键行为"项目，A/B/C 三段里 B 和 C 都还没打通，
不是一次补丁能完成的。诚实地说，今晚做不到。

## 3. 分阶段方案（按可完成度排序）

### 阶段 1（现在就能用，不需要固件）

- 用 `bind_button` 把 **"切换拍摄模式"** 绑到目标按键（需要先运行 `tools/apply_hidden_menu.py` 打开隐藏条目）；
- 按键 → 循环驱动模式（单张 → Hi+ → Hi → MID …）。

**局限**：循环而非"按住即 Hi+"；且隐藏条目在每次开机后需要重新打补丁才可选。

### 阶段 2（可行的固件化第一步）

把"校验函数恒真"做进 DAT（8 字节，位置已确认：明文 `0x29059FC4` 与 `0x369479C4`），
让隐藏条目**永久可选**。此后阶段 1 的操作一次设置、长期有效。

这一步的工具已写好：`tools/build_hidden_menu_dat.py`。

### 阶段 3（真正实现 B/C）

需要先解决两个未解问题：

1. **按键事件入口**：需要找到"按下/松开"事件的分发点。
   已知事件→处理器表在 `0x595BCD8`（16 字节一项），但没有任何代码引用它；
   下一步只能靠运行期内存取证（改进方案：写一个自包含的 ARM64 扫描器，一次扫描输出命中地址，
   避免上百次 USB 往返）。
2. **驱动模式设置调用**：`sequence_set_drive_mode::run()` = `0x3442BD4`，
   需要 13 个字段的模型对象；要么找到更底层的 `PID_SET_DRIVE_MODE` 组包函数，
   要么找到"从属性值触发序列"的通用入口。

## 4. 已知可复用的东西

* 运行期补丁通道：`tools/apply_hidden_menu.py`、`tools/poke_addr.py`、`tools/poke64.py`（64 位偏移写入）；
* 绑定读写：`analysis/camprop.py`（只读）、`tools/ap_session.py`（读写，偶发 error 129）；
* 绑定槽位表：`0x02CF0404–0x02CF041F`，AF-ON=`0x041B`、MOVIE=`0x041C`（真机验证过）；
* 隐藏菜单：校验函数 vaddr `0x1B6E1C4`，改成 `mov w0,#1 ; ret` 即可放出所有条目。
